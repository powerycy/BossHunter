# 招呼语优化预览与确认

## 目标

在保留原有招呼语生成与发送流程的前提下，把风格优化从“自动改写并直接进入发送”调整为可选、可预览、可人工确认的步骤。

## 配置

- `greeting_style_suggestions`：是否生成优化建议，默认开启。关闭后只生成一版招呼语，不再调用风格优化。
- `greeting_auto_apply_style`：是否自动采用优化版，默认关闭。仅在生成优化建议时生效。

## 状态规则

1. 生成器始终保存原文；有优化结果时同时保存优化版和问题说明。
2. 默认配置下，有两个版本的岗位进入 `pending` 状态，页面可预览原文、优化版和问题说明。
3. `pending` 状态不能发送，也不会进入后台发送队列。
4. 用户可以保留原文、采用优化版，或提交不超过 300 字的手工编辑内容。
5. 选择操作必须显式确认；确认后记录选择类型和确认时间。
6. 已人工确认的招呼语不会被后续生成任务覆盖。
7. 开启“自动采用优化版”后，优化版直接进入可发送状态，但仍在页面保留两版内容供查看。
8. 点击“发送招呼语”只发送当前最终版本，不会再次调用招呼语生成，也不会把岗位退回待确认状态。

## 接口

- `POST /api/jobs/<job_id>/greeting-selection`
- 请求字段：`selection`（`original`、`optimized` 或 `edited`）、`confirmed: true`；手工编辑时还需提供 `greeting`。
- 未确认、内容为空、内容超长、岗位状态不允许或已发送时，接口拒绝修改。

## 发送边界

页面单条发送、批量发送和后台发送队列共用同一状态边界：未人工确认且未启用自动采用的候选内容不能发送。预览和确认只修改本地岗位记录，不会自行触发对外发送。
