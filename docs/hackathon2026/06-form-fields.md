状态：已按官方自助报名说明整理；登录后的实际表单仍需逐项复核。自助通道适合使用本地 Coding 工具并自行部署的作品，BossHunter 选择此通道。

## 可直接粘贴

### 项目名称

BossHunter——把岗位筛选、沟通和跟进交给 AI，把投递决定留给人

### 一句话介绍

一个本地优先的 AI 求职工作流：完成岗位预筛、匹配分析、沟通草稿和状态跟进，发送前保留人工确认。

### 项目介绍

BossHunter 解决的不是“怎么投得更多”，而是集中求职时反复筛岗位、改招呼语、记跟进状态和按 JD 调整简历的重复劳动。系统先用硬条件预筛，再结合完整 JD 与简历做 AI 深度评分和排序，生成个性化招呼语；用户决定哪些岗位继续。真实版本在本地连接用户已登录的 Chrome，通过时间窗、每日上限、随机间隔、停止和人工确认控制敏感动作。收到 HR 回复后，系统识别待回复或简历请求，并基于原始经历生成定制简历草稿，不新增事实，也不自动发送。比赛版提供无需账号的隔离沙盒，用匿名简历和模拟 JD 展示关键闭环。

### 解决的问题

求职者的注意力被岗位初筛、重复沟通、状态记录和材料调整切碎。现有自动化容易把目标变成无人值守海投。BossHunter 把 AI 放在信息处理和草稿生成的位置，把外部发送和最终选择留给人。

### 创新点

1. 两阶段评分：低成本硬条件预筛后再做完整 JD 深度分析。
2. 决策与执行分离：AI 输出理由、风险和草稿，敏感动作需要人工确认。
3. 长链路状态化：采集、评分、确认、发送、回复、简历请求和失败恢复统一进入可观察工作台。
4. 本地隐私与公开评审兼容：真实模式本地运行；公网只部署不含账号、后端和用户数据的可复现沙盒。
5. 定制简历强调事实边界：只重排和改写原始经历，不为匹配岗位发明信息。

### 技术说明

Python 3.10+ 负责 CLI、任务编排、AI 服务、浏览器会话、SQLite 和 Bottle API；React、TypeScript、Vite 与 Tailwind CSS 负责 Web 工作台。Browser Runtime 通过 CDP 连接用户本地 Chrome，AI 层支持 Anthropic 与 OpenAI 兼容协议。任务运行器处理停止信号、人工确认等待、监测队列、错误恢复和状态快照。GitHub Pages 只构建评委沙盒，不携带真实后端或用户数据。

### AI 参与方式

本次比赛打磨使用 Codex 辅助进行代码审计、评委沙盒实现、构建与浏览器回归、GitHub Pages 部署和报名材料整理。人负责问题定义、产品边界、事实复核、是否采用修改及最终提交。没有用 AI 编造用户反馈、效果指标或个人经历。

### 风险与边界

真实模式依赖用户自行登录的招聘平台。第三方平台自动化可能违反其用户协议，项目不宣传绕过检测，只建议个人求职期间本地、短期、低频使用，并在敏感动作前人工确认。公网演示不访问任何招聘平台。
